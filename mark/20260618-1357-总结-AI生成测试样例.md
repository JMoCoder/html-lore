## 测试目标

验证第一版 AI HTML 生成 v2 是否满足：

- 多格式输入可解析。
- LangGraph 多 Agent 链路可跑通。
- 生成内容符合用户需求。
- 样式参考能影响结果。
- 安全门禁能阻断危险内容。
- 异步任务状态可见。
- 成功结果进入资料库 `inbox`。
- legacy fallback 可用。

## 必测样例

### Case 1：Markdown 基础生成

输入：

```text
文件：material-basic.md
需求：把这份材料整理成一篇适合新手阅读的 HTML 知识笔记。
theme：default
target_use：personal
style_preference：report
reference_style：default
```

预期：

- ParsedDocument.plain_text 非空。
- RequirementBrief.user_goal 明确。
- PlanDraft.section_plan 至少 3 节。
- ContentDraft.sections 覆盖主要内容。
- HtmlDraft.html 可渲染。
- Write Gateway 写入 `inbox`。

验收点：

- 生成页面标题明确。
- 结构清晰。
- 没有明显胡编。
- 移动端可读。

### Case 2：HTML 输入重组

输入：

```text
文件：source-page.html
需求：保留主要信息，重组为更清晰的知识卡片页面。
theme：light
target_use：share
style_preference：website
```

预期：

- HTML 中 script 等危险内容不进入最终产物。
- 主要文本被提取并重组。
- SafetyReport.ok = true。
- 分享安全规则通过。

验收点：

- 原 HTML 主要内容未丢失。
- 页面不是简单复制原 HTML。
- 外链和脚本被安全处理。

### Case 3：PDF 摘要型生成

输入：

```text
文件：report-sample.pdf
需求：总结成一篇管理层可快速浏览的 HTML 简报。
theme：default
target_use：share
style_preference：report
```

预期：

- MarkItDown 解析成功，或失败后有 warning。
- ContentDraft.summary 有管理层摘要。
- 页面包含关键结论和分节。
- 解析不足时不要求用户补材料，只在 warnings 中记录。

验收点：

- 不堆砌 PDF 原文。
- 重点清晰。
- 没有明显无依据结论。

### Case 4：样式参考文件

输入：

```text
主文件：material-style.md
样式参考：style-reference.html 或 style-reference.pptx
需求：参考样式文件，生成一页适合展示的 HTML 页面。
theme：default
target_use：share
style_preference：ppt
reference_style：file
```

预期：

- reference_file metadata 被记录。
- style_hints 或 StyleBrief.reference_sources 包含参考文件。
- StyleBrief.design_mode = reference_guided_design。
- 最终页面风格明显受参考影响，但不是像素级复刻。

验收点：

- 色彩/布局/层级能体现参考倾向。
- 没有直接复制不可控外链或脚本。
- 可读性优先。

### Case 5：安全失败阻断

输入：

```text
文件：unsafe.html
内容包含 script、iframe、form、tracking pixel 或危险外链。
需求：生成可分享 HTML。
target_use：share
```

预期：

- Safety Reviewer 或 Write Gateway 阻断危险内容。
- job 失败或自动修复后通过。
- 若失败，error code = safety_blocked。
- 不写入半成品。

验收点：

- content 目录不留下危险产物。
- metadata 不留下孤立记录。
- 前端显示安全失败摘要。

### Case 6：Verifier 回退

输入：

```text
文件：material-missing.md
需求：必须包含 A、B、C 三个部分，其中 C 容易被遗漏。
```

预期：

- Planner 将 A/B/C 写入 execution_checklist 或 success_criteria。
- Content Writer 初稿如果漏 C，Verifier 返回 route_back_to = Content Writer。
- 重跑后 C 被补上，或任务失败并有明确错误。

验收点：

- 回退由 ValidationReport 驱动。
- Runtime 不用关键词判断 C 是否遗漏。

## 可选样例

### Case 7：Word 输入

目标：

- 验证 Word 文档可由 MarkItDown 解析。
- 生成报告型 HTML。

### Case 8：PPT 输入

目标：

- 验证 PPT 文本结构可提取。
- 生成展示型 HTML。

### Case 9：解析 warning

目标：

- 构造低文本 PDF 或解析不完整文件。
- 验证 warnings 进入 ParsedDocument。
- Agent 保守生成，不要求用户补材料。

### Case 10：legacy fallback

目标：

- 设置 `HTML_LORE_AI_GENERATION_ENGINE=legacy`。
- 确认旧生成路径仍可跑。
- 设置 `v2` 后确认新路径可跑。

## 人工真实验收清单

需要准备：

```text
1 个 Markdown 或 TXT 文件
1 个 HTML 文件
1 个 PDF 文件
1 个 Word 或 PPT 文件
1 个样式参考文件
1 个危险 HTML 文件
```

人工评价维度：

```text
内容准确性
结构清晰度
视觉质量
移动端可读性
样式参考体现程度
安全拦截效果
任务状态可理解性
生成结果落库正确性
```

建议评分：

```text
5 = 超出预期，可作为默认能力
4 = 达到预期，少量细节可优化
3 = 勉强可用，需要继续优化
2 = 不稳定，不应发布
1 = 失败
```

第一版发布门槛：

```text
Markdown: >= 4
HTML: >= 4
PDF: >= 3
样式参考: >= 3
安全失败: 必须通过
状态展示: 必须通过
inbox 落库: 必须通过
```

## 测试数据安全

- 测试文件不得包含真实密钥。
- 测试文件不得包含个人隐私。
- 危险 HTML 样例只使用假 URL 和无害 payload。
- 截图和日志不得输出 API key。
- stage_trace 不记录完整 prompt 和模型内部推理。
