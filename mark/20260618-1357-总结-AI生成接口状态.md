## 接口范围

第一版复用现有接口，尽量不破坏兼容：

```text
POST /api/ai/material-jobs
GET  /api/ai/jobs
GET  /api/ai/jobs/{job_id}
POST /api/ai/jobs/{job_id}/retry
POST /api/ai/jobs/{job_id}/cancel
GET  /api/ai/runs
GET  /api/ai/runs/{run_id}
```

建议新增：

```text
GET /api/ai/jobs/{job_id}/trace
```

用途：返回某个生成任务的阶段 trace、执行清单摘要和当前错误摘要。

```text

  - completed_at
```

注意：

- `stage_trace` 只放阶段摘要，不放完整 prompt 和模型内部推理。
- `execution_checklist` 可只返回公开摘要，隐藏过长中间内容。
- `state_snapshot` 第一版可只存服务端，不默认 API 返回。

## Job Status / 任务状态

```text
pending      -> 等候中
running      -> 处理中
completed    -> 已完成
failed       -> 失败
canceled     -> 已取消
canceling    -> 正在取消
```

前端建议：

- `pending/running`：显示阶段。
- `completed`：显示打开结果。
- `failed`：显示错误摘要和重试。
- `canceled`：显示取消状态。

## Stage / 阶段状态

```text
queued                    -> 等候中
parsing                   -> 解析中
parse_failed              -> 解析失败
analyzing_requirements    -> 分析需求中
planning                  -> 规划中
writing_content           -> 撰写内容中
executing_tools           -> 调用工具中
designing_style           -> 设计样式中
coding_html               -> 生成 HTML 中
verifying                 -> 验证中
safety_checking           -> 安全检查中
finalizing                -> 收尾中
writing                   -> 写入资料库中
completed                 -> 已完成
failed                    -> 失败
canceled                  -> 已取消
```

## 错误码

建议第一版统一错误码：

```text
parse_failed
schema_validation_failed
llm_request_failed
llm_output_invalid
tool_failed
verification_failed
safety_blocked
write_failed
build_failed
job_canceled
unknown_error
```

前端文案：

```text
parse_failed              -> 文件解析失败
schema_validation_failed  -> AI 输出结构校验失败
llm_request_failed        -> AI 请求失败
llm_output_invalid        -> AI 返回内容不可用
tool_failed               -> 工具调用失败
verification_failed       -> 需求验证未通过
safety_blocked            -> 安全检查未通过
write_failed              -> 写入资料库失败
build_failed              -> 构建索引失败
job_canceled              -> 任务已取消
unknown_error             -> 未知错误
```

## 重试策略

```text
parse_failed
  -> retryable = true

schema_validation_failed
  -> retryable = true

llm_request_failed
  -> retryable = true

verification_failed
  -> retryable = true

safety_blocked
  -> retryable = false 或 true，取决于是否可自动修复

write_failed
  -> retryable = true

build_failed
  -> retryable = true
```

第一版建议：

- 失败任务可重试整条 job。
- 暂不支持从某个 stage 局部重试。
- 内部 Agent 节点可按 `max_same_node_retries=2` 自动重试。

- 模型内部推理。
- 大段原始文件内容。
- 未过滤的用户敏感信息。
