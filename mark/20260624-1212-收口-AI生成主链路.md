# 收口：AI 生成主链路

**时间**：2026-06-24 12:12
**状态**：已完成

---

## 需求背景

本阶段目标是把“根据用户上传文件或自然语言需求生成 HTML 笔记”的 AI 生成 v2 主链路做成可交付基线。此前已确定生成模块要采用 LangGraph 风格的多智能体协作，runtime 负责状态控制、工具调用、安全和写入，业务内容判断尽量由 agent 完成。

## 解决方案

采用 generation v2 多节点链路作为主实现：

```text
Ingest
-> RequirementAnalyst
-> Planner
-> ContentWriter
-> StyleDesigner
-> HTMLCoder
-> Verifier
-> SafetyReviewer
-> Finalizer
-> WriteGateway
```

当前版本将 AI 生成主链路定义为“第一版可交付基线”：主流程闭环、真实模型可跑通、结果能写入资料库、过程可追踪，并且守住隐私和安全边界。后续工作转入体验增强、视觉质量提升和第二阶段能力扩展。

## 实施细节

- 前端“用 AI 创建”已切到自然语言主导：
  - 取消 `自动/链接/文件/书籍/主题` 输入类型选择。
  - 文本框提示改为“请文字描述你想生成的内容”。
  - 主材料文件上传变为可选。
  - 参考样式文件上传放入“更多”设置，支持 JPG/PNG、HTML、PDF、PPT/PPTX。
  - 无文件纯文本需求也统一走 `/api/ai/material-jobs` 和 generation v2。
- 后端支持：
  - `/api/ai/material-jobs` 可接受主文件、无主文件纯文本、参考样式文件。
  - 无文件时创建虚拟 `prompt.txt` 进入 v2 图。
  - MarkItDown 作为增强解析链路，basic parser 保底。
- 多 agent 运行态：
  - `HTMLCoder` 改为直接返回原始完整 HTML，不再把整页 HTML 包进 JSON。
  - `Finalizer` 改为 runtime 组装，不再调用 LLM 覆盖 HTMLCoder 成品。
  - Planner / ContentWriter prompt 增加结构化输出范围约束，减少 schema retry。
  - schema loader 兼容 enum 大小写、`null` list/object 默认值，减少无意义失败。
  - agent provider 瞬时失败支持重试。
- 状态与可观测：
  - `stage_trace` 增加 `duration_ms` 和安全元数据摘要。
  - 重试 attempt 标记为 `retrying`，避免状态页残留多个 `started`。
  - 新增 `agent_artifacts` 脱敏版智能体输出摘要，覆盖 RequirementAnalyst / Planner / ContentWriter / StyleDesigner / HTMLCoder / Verifier / SafetyReviewer / Finalizer。
  - 前端任务详情已显示处理过程、智能体输出、检查项、技能。
- 隐私与安全边界：
  - 不保存完整 prompt。
  - 不保存上传原文。
  - 不保存参考文件正文。
  - 不保存 HTMLCoder 完整 HTML。
  - 对用户 prompt、上传正文、参考样式提取值等做脱敏。

## 遇到的问题

- `HTMLCoder` 最初把完整 HTML 包在 JSON 字段中返回，真实供应商下慢且不稳定。已改为 raw HTML 输出协议。
- `Finalizer` 曾重新调用 LLM，导致完整 HTML 被覆盖成短说明页。已改为 runtime 组装最终 proposal。
- Planner / ContentWriter 曾出现 schema retry 和长输出不稳定。已通过 prompt 范围约束和 schema 兼容收敛。
- `agent_artifacts` 初版曾把 fake 测试中的私有正文、参考样式色值写入 job 记录。已增加 artifact 脱敏与测试覆盖。
- HTMLCoder 仍是主要耗时节点。真实样例中约 226-350 秒，当前认为五分钟级生成一篇完整 HTML 笔记在后台任务形态下可接受。

## 最终结果

AI 生成 v2 主链路已达到“第一版可交付基线”：

- 文件输入、纯文本输入、参考样式文件均可进入 v2 生成链路。
- 真实 NewAPI / gpt-5.5 smoke 跑通多类样例。
- 样式 URL 被当作风格参考处理，不当作内容来源。
- 内容 URL 在未接入抓取时会诚实声明未读取网页正文，不伪装已抓取。
- 模糊需求可生成通用 HTML 介绍页，并保守声明缺少具体公司/参数时不做收益承诺。
- 输出可写入资料库并进入 inbox。
- 任务过程可查看阶段耗时和脱敏 agent 输出摘要。

## 值得注意

- 当前可以断言“主链路可交付”，但不能断言“商业化视觉质量完成”。
- 生成模块是核心能力，第一阶段不宜过早为了速度牺牲质量；五分钟级后台生成暂时可接受。
- runtime 不应参与业务内容判断，但必须负责状态、脱敏、安全、重试和写入边界。
- agent artifacts 很有价值，但必须严格脱敏。尤其是 source summary、上传正文、参考样式色值、HTMLCoder 完整 HTML 都不应直接落库。
- 链接能力尚未实现抓取，当前只是自然语言输入。后续接入链接抓取时要明确“内容来源链接”和“样式参考链接”的路由边界。

## 2026-06-26 验证补充：复杂说明页真实生成

本轮用真实 provider 跑了一次复杂任务：根据当前代码库生成一篇 HTML 笔记，解释 HTMlore AI 生成逻辑、各智能体、runtime/code 控制边界、模型控制边界、节点、edge、loop、不同用户输入和扩展选项的影响。

验证过程结论：

- 第一次本地联调脚本使用非流式请求，主链路跑到 SafetyReviewer 后触发回到 HTMLCoder 的修订 loop；第二轮 HTMLCoder 连续遇到上游网关 `524`，约 126 秒后被中转 API 截断。
- 524 是上游网关等待模型服务响应超时，不代表 API key 错误，也不代表本地代码或 agent 逻辑失败。
- 正式 provider adapter 原本使用 `stream: true`，本地脚本改成流式后，完整链路成功跑通。
- 成功样例写入本地库：`data/content/generated/2026/06/htmlore-ai.html`，元数据位于 `data/meta/items/generated/2026/06/htmlore-ai.yml`。
- 本次链路耗时约 6 分 12 秒，HTMLCoder 输出约 30537 字符，Verifier 评分 0.93，SafetyReviewer 风险等级 low。
- 验证中出现过一次 HTMLCoder TLS 连接中断，provider retry 后成功，证明节点级 provider 重试是必要的。

由此做出的实现调整：

- 保留“无总任务时长硬截断”的设计，不因为复杂任务耗时长而误杀。
- 保留节点级 schema retry、provider retry、最大图步数、reviewer 修订轮次上限，防止无限循环。
- 将 chat provider timeout 从硬编码 45 秒改为配置项，默认 `HTML_LORE_AI_PROVIDER_TIMEOUT_SECONDS=180`。
- embedding timeout 独立为 `HTML_LORE_AI_EMBEDDING_TIMEOUT_SECONDS=45`，避免短请求被长生成策略拖累。
- AI 生成输出上限独立为 `HTML_LORE_AI_GENERATION_MAX_TOKENS=12000`，不再复用问答短回答的 `HTML_LORE_AI_MAX_RESPONSE_TOKENS`。

这次验证说明：HTMLCoder 的质量优先策略应保留，不能因为中转 API 不稳定就压低生成质量；需要优化的是 provider 连接、流式响应、重试与可观测性。
