# 生成 v2 回归基线

**日期**：2026-06-23
**范围**：AI HTML generation v2 第一阶段文件解析与参考样式文件链路

## 目标

本基线用于锁定“用户上传文件 + 用户需求 -> 生成 HTML 笔记”的底层链路，避免后续做生成质量增强时破坏以下能力：

- 第一阶段文件类型路由。
- MarkItDown 优先、basic parser 降级。
- API 层 `file + reference_file` 双文件上传。
- v2 job 阶段 trace、skill trace、隐私字段脱敏。

本基线不评估商业化视觉质量；视觉质量另建真实样例评审集。

## 已知边界

- 前端“用 AI 创建”已提供可选参考文件入口；侧栏“生成笔记”仍不接入该入口，避免与知识库上下文生成混用。
- 纯文字需求已切到 generation v2；但链接抓取仍未实现，文本框中的 URL 暂时作为用户需求的一部分交给 Planner 理解，不主动抓网页。
- 2026-06-23 真实无文件样例验证发现：v2 全链路可跑通，但 HTMLCoder 节点把完整 HTML 包在 JSON 字段中返回，真实供应商下耗时很长，且容易遇到空响应/超时/结构化 JSON 不稳定。已修复 Finalizer 覆盖 HTMLCoder 产物的问题，并新增 provider 瞬时失败重试。
- HTMLCoder 已改为“原始完整 HTML 文本”输出协议，不再把整页 HTML 包进 JSON 字段；Runtime 将原始 HTML 包装为 `HtmlDraft` 并继续走 Verifier / SafetyReviewer / Finalizer。
- generation v2 `stage_trace` 已补充节点 `duration_ms` 与安全元数据摘要（如 output chars、section count、score、retry count），用于状态页和回归定位，不携带 prompt 或原始资料正文。
- 非文本格式的自动化测试通过 mock MarkItDown 锁定路由；真实质量验收仍需使用本地私有 PDF、Office、图片样例跑 smoke。
- 当前基线只验证解析、路由、状态、脱敏和 reference file plumbing，不判断生成出来的 HTML 是否达到商业交付质量。

## 真实样例验证记录

### 2026-06-23 无文件 v2 生成

已跑样例：

| 样例 | 状态 | 结论 |
| --- | --- | --- |
| 纯主题：虚拟电厂培训页 | 通过 | Raw HTML 协议后可生成约 25KB 完整 HTML，Verifier 与 SafetyReviewer 通过，最终写入成功。 |
| 链接作为样式参考：参考 Apple 风格生成工商业储能页面 | 通过 / 性能仍偏慢 | 三个结构化节点均一次通过；HTMLCoder 返回约 24.7K 字符，最终文件约 29.8KB，Verifier score 0.91，Safety low。页面将 Apple URL 作为风格参考处理，未当作内容来源。 |
| 链接作为内容来源：energy.gov 虚拟电厂链接 | 通过 / 未抓取网页 | 三个结构化节点均一次通过；HTMLCoder 返回约 17.5K 字符，最终文件约 21.4KB，Verifier score 0.86，Safety low。页面明确说明当前未包含网页正文，保留参考链接，未伪装读取网页。 |
| 模糊需求：储能业务介绍页 | 通过 / 性能仍偏慢 | 三个结构化节点均一次通过；HTMLCoder 返回约 29.9K 字符，最终文件约 34.9KB，Verifier score 0.91，Safety low。内容采用通用储能业务介绍，并说明未提供具体公司/参数。 |

修复项：

- `FinalizerAgent` 改为 runtime 组装最终 `CreateNoteProposal`，不再调用模型改写 HTML。
- 增加测试确保 `create_note_proposal.html == html_draft.html`。
- generation agent 增加 provider 瞬时失败重试，覆盖空响应/网络抖动一类临时错误。
- `HTMLCoderAgent` 改为调用 `complete_text`，要求模型直接返回完整 HTML；新增 raw HTML 提取、provider `complete_text`、HTMLCoder 完整 HTML 接受/拒绝测试。
- `stage_trace` 增加 `duration_ms` 和安全元数据摘要；前端任务详情显示节点耗时和输出摘要，便于定位慢节点。
- `agent_artifacts` 增加脱敏版智能体输出摘要，用于前端展示多 agent 协作过程。保存范围包括 RequirementAnalyst / Planner / ContentWriter / StyleDesigner / HTMLCoder / Verifier / SafetyReviewer / Finalizer 的白名单摘要字段；不保存完整 prompt、原始上传正文、参考文件正文或 HTMLCoder 完整 HTML。
- agent 节点重试时，旧 attempt 会标记为 `retrying` 并记录耗时、错误类型和 retry count，避免状态页残留多个 `started` 节点造成误判。
- schema loader 对 enum 字段做轻量标准化，兼容模型返回 `DONE` / `done` / 空格或横线形式，减少无意义 schema retry。
- Planner / ContentWriter prompt 增加结构化输出范围约束，真实样例中不再出现 schema retry。
- HTMLCoder prompt 增加性能预算，要求首版 HTML 完整但避免过长 CSS 和装饰；内容 URL 样例已降至约 17.5K 字符，但样式参考和模糊需求场景仍偏大。

下一步验证前置项：

- HTMLCoder 仍是主耗时节点，真实样例耗时约 226-350 秒；下一步应评估是否拆分编码策略、压缩 StyleBrief、或引入更明确的首版页面尺寸预算。
- 链接抓取尚未实现。当前 URL 只作为自然语言输入；内容 URL 样例已要求页面诚实声明未读取网页正文。
- 状态页已能利用 `stage_trace.duration_ms` 和 `agent_artifacts` 展示节点耗时与脱敏输出摘要；后续可进一步做独立任务详情页和更强的运行时进度体验。
