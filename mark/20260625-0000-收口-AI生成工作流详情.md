# 收口：AI 生成工作流详情

**时间**：2026-06-25 00:00
**状态**：已完成

---

## 需求背景

本轮在 AI 生成主链路已可交付的基础上，继续完善前端可观测性和后台记录能力。重点不是继续改生成内容判断，而是把 LangGraph 多智能体链路的运行过程、生成历史、AI 运行记录和静态 demo 展示拉平到一个可发布的小版本。

## 解决方案

采用“后端只暴露脱敏运行摘要，前端提供可视化详情”的方式收口。生成任务通过 SSE + 轮询降级刷新；生成历史、运行记录、demo 和文档统一到 `1.0.5` 小版本。

## 实施细节

- AI 生成历史新增工作流详情窗口：
  - 展示 LangGraph 阶段状态。
  - 展示 agent 输入摘要、输出摘要、警告、元数据、token 用量和轻量质量评分。
  - “打开笔记”按钮在生成完成前置灰，完成后可打开生成笔记。
- 新增生成任务 SSE 更新接口，并保留轮询降级。
- 生成历史列表优化：
  - 主页生成队列保持简洁，只展示最近任务。
  - 设置页新增 AI 生成历史专属入口。
  - 完成任务显示打开入口，失败任务显示重试入口，运行中/等待中显示状态与队列序号。
- AI 运行记录优化：
  - 左侧主字段加宽，避免正常条目换行。
  - 列表隐藏内部 `qa_agent_*` 等运行 id。
  - 失败条目不在列表展示错误正文，仅保留失败标签；错误详情在详情页查看。
  - 历史运行可从 trace 的开始/结束时间回填耗时。
- 前端导航与会话历史优化：
  - 右侧 AI 对话的新建/历史入口更明确。
  - 主页与阅读页均按当前上下文加载会话历史。
  - 静态 demo 同步当前工作台界面。
- 文档与版本：
  - 三语 CHANGELOG 增加 `1.0.5`。
  - demo changelog 页面与 manifest 摘要同步到 `1.0.5`。
  - 版本号、PWA cache、provider user-agent 统一升级到 `1.0.5`。

## 遇到的问题

- 前端生成历史、AI 运行记录和工作流详情的职责边界容易混在一起。本轮将“列表只展示状态和入口，详情页展示排错信息”作为当前规则。
- 运行记录里曾显示内部 agent id 和过多错误正文，影响可读性。已改为列表隐藏内部 id，失败正文留在详情中。
- 历史记录中有些运行缺少耗时字段。已通过 trace 的开始/结束时间回填。

## 最终结果

AI 生成主链路的可观测界面、历史入口、运行记录和静态 demo 已可作为 `1.0.5` 小版本基线。

## 值得注意

本轮继续保持以下限制：

- 不在公开任务详情展示原始 prompt。
- 不展示上传文件正文。
- 不展示参考样式文件正文。
- 不展示 HTMLCoder 的完整 HTML 输出。
- 不展示 API Key。
- 费用估算字段已取消，不在 UI 或公开详情中展示。

保留的运行信息只用于可观测性和排错，包括脱敏摘要、阶段状态、耗时、token 用量、轻量质量评分和警告。

下一环境开始前，当前状态可作为 AI 生成前端可观测性的基线版本。后续重点可以进入：

- AI 生成结果视觉质量优化。
- design skill / style tools / 模板能力设计。
- 链接抓取第二阶段。
- HTML 修改模块。
- 当前静态前端复杂度继续上升时，需要重新决策是否引入 React/Vue/Vite 等组件化架构。
