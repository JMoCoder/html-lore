# AI 生成外部工具优先级

## 一句话概括

AI 生成样式优化应优先引入能验证真实渲染和结构化输入的受控工具，而不是直接引入外部模板项目或本地 coding-agent CLI。

## 背景

当前 AI 生成 v2 已有内部原创 skill 路由：默认 skill 是通用底座，可选增强 skill 用于 presentation、architecture、component pattern 等场景。后续评估 `effective-html`、`pakco-html`、`html-anything` 等成熟项目时，仍应保持当前架构原则：

- [[LangGraph]] 负责工作流状态和节点编排。
- Agent 负责内容、风格和业务判断。
- Runtime / tools 负责受控执行、状态、安全和写入。
- skill 是 Markdown 驱动的 LLM 工作手册，不是可执行工具。

## 核心内容

在继续使用内部原创 skill 承接外部项目通用经验的前提下，外部工具/依赖候选优先级如下：

1. **Playwright / 系统 Chrome 渲染验收 tool**
   - 目标：自动发现空白页、横向溢出、标题重叠、卡片遮挡、移动端破版、截图像素异常等问题。
   - 价值：最直接提升样式可靠性和商业化交付感。
   - 边界：Runtime 只输出 `VisualCheckReport`，不直接改 HTML；HTMLCoder 根据报告修订。

2. **结构化表格 / 数据解析 tool**
   - 目标：为 Excel / CSV / JSON / SQL / 数据报告类输入保留表头、单位、字段类型、时间序列和分组结构。
   - 候选：Python `csv`、`openpyxl` 优先；`pandas` 偏重；JS `xlsx` 不建议服务端优先选。
   - 边界：不替代 MarkItDown，而是作为 Ingest 的增强解析分支。

3. **HTML/CSS 安全净化 tool**
   - 目标：增强当前自研 `html_safety`，降低 unsafe HTML 进入资料库或预览的风险。
   - 候选：DOMPurify、bleach、html5lib 等方向。
   - 边界：主要是安全增强，不是样式质量主线；过度净化可能破坏合法 CSS。

4. **CSS 内联 / PNG 导出 tool**
   - 目标：支持公众号、知乎、邮件、社交图、PNG 导出等发布场景。
   - 候选：`juice`、Playwright screenshot、modern-screenshot 等。
   - 边界：等平台发布和分享需求明确后再评估，不提前进入当前样式优化主线。

短期不建议进入项目：

- 本地 coding-agent CLI adapter。
- 整体 Next / React / Tailwind 应用。
- 外部模板 runtime 直接调用。
- canvas FX / heavy animation library。

> [!tip] 关键要点
> 最值得优先评估的是浏览器渲染验收 tool，因为它能把“页面看起来坏了”转为结构化反馈，再交给 Agent 修订，符合“Agent 判断业务，Runtime 控制状态和工具”的边界。

> [!warning] 注意事项
> 不要把 `pakco-html` 或 `effective-html` 的模板、示例语料、prompt 直接复制进仓库。更稳妥的路径是外部经验 -> 能力标签 -> Planner `tool_needs` -> 内部原创 skill -> 必要时调用受控 tool。

## 实际应用

后续真正进入实现时，可按以下顺序开 Decision Gate：

1. 是否引入 Playwright/系统 Chrome 作为 v2 visual check tool。
2. visual check 运行在哪些模式：开发模式、高质量模式、失败重试模式，还是全部任务。
3. `VisualCheckReport` 的 schema：溢出、重叠、空白、移动端、截图像素等字段如何定义。
4. 表格结构化解析是否用 `openpyxl` 作为第一步可选依赖。
5. HTML/CSS 净化是否增强当前自研 `html_safety`，以及净化发生在预览前还是写入前。
