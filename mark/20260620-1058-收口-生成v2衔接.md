## 需求背景

本阶段从 `mark/20260618-1755-收口-AI生成v2.md` 继续推进。上一次收口时，AI 生成 v2 的 LangGraph/多 Agent 底座、真实 provider 调用和基础状态链路已经搭好，但真实端到端生成仍卡在 `Verifier` 多轮不放行，尚未达到可交付。

本次目标是继续把“用户上传文件 + 需求/选项 -> 生成 HTML 笔记 -> 写入 inbox”的生成链路推到本地可用，并优化创建入口、状态展示和 checklist 过程记录，为后续做商业级 HTML 生成质量提升打基础。

## 解决方案

本阶段没有在底座层写死具体风格或摘要样式，而是保持以下架构原则：

- Runtime/基础代码层只负责状态控制、文件解析、工作流编排、模型调用、工具调用、安全检查、写入资料库、失败降级。
- 默认生成不注入强风格约束，让模型根据文件内容和用户自然语言自主规划。
- 特定风格、用途、受众、主题等要求通过创建时的拓展选项进入运行态上下文，而不是写死在基础代码层。
- 更高级的商业化设计能力后续通过 `skill/tools` 按需增强，例如设计方法、检查清单、图表表达、行业报告组件、参考案例等。
- 用户自然语言优先级最高，拓展选项用于补充或澄清，不应覆盖用户明确表达。

本阶段重点解决三类问题：

1. 前端创建入口可用性：上传文件入口、更多设置、长提示词输入、窄屏/AI 侧栏开启后的布局。
2. 生成链路状态可信度：任务详情能看到阶段 trace、skill trace、checklist 状态，而不是所有检查项一直 pending。
3. 真实生成最小变量验证：用户只上传材料、不输入提示词、不设置风格，验证 v2 自动路由是否能产出可用 HTML 笔记。

## 遇到的问题

1. 创建提示词框使用浏览器原生 `resize: vertical` 时，输入文字会触发 JS 自动高度逻辑，把用户手动拉高的高度压回去。

解决：关闭原生 resize，改为自定义下边框拖动；输入事件只在内容超过当前高度时扩高，不再自动缩小。

2. AI 侧栏拉宽后，主页创建区仍按四列宽屏布局排列，导致输入框、按钮和选项区域挤乱。

解决：为 `.workspace` 增加 container query，根据主区实际宽度而不是浏览器宽度折行。

3. 窄输入框下 placeholder 会从上传图标右侧露出。

解决：在空输入框状态增加右侧遮罩层，上传图标保持更高 z-index；输入真实内容后遮罩不影响内容显示。

4. 生成任务的 checklist 在任务完成后仍全部显示 `pending`。

原因：Planner 只生成了 checklist，后续 agent 没有把自己的执行结果回写到 checklist。

解决：在 v2 agent 基类中增加 checklist 状态回写，Verifier/SafetyReviewer 根据报告可回写 `warning` 或 `failed`。
